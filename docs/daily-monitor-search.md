# 每日监测搜索、订阅与二次研究

当前入口：`agent-workflow/financing/dispatch.mjs`。全部 AI 融资与六类消费 AI 硬件融资复用同一原文、事件、研究和发布链。具身智能、机器人本体及核心部件主营企业按原文排除；社群、Builders、独立 FDE 和硬件产品内容不进入本流程。

## 搜索网关

采集和融资二次研究统一调用 `tools/lib/search-gateway.mjs`。默认 Anysearch → 可选 Brave → Tavily → Exa，结果不足时使用 Bing RSS。AIHOT 和媒体订阅另行采集，不占搜索引擎调用数。

- 中文查询保持中文；`site:` 和 `-site:` 转成提供方支持的域名参数，并在结果端校验。
- URL 去追踪参数、去重；同查询并发合并，非空缓存 6 小时、空结果 15 分钟。
- 401/403、402、429 分别记录认证、配额和限流，本轮停止请求该提供方。超时、响应结构错误、空结果分别记录，失败不能伪装成零融资。
- 采集最多 160 次付费请求，研究默认 120 次；研究的 `--search-request-budget` 可设更低预算。没有配置的接口不调用，不开户、不购买额度。
- 39 条国内外初始查询先执行，覆盖全部融资大类与六类消费硬件；之后执行订阅失败源的定向补查，避免补充来源耗尽主流程预算。
- `inspect-search-providers.mjs --live=true --env-file=<本地环境文件> --output=<私有运行文件>` 每个已配置接口探测一次，不输出凭据。

2026-10-01 本机观察：Anysearch、Tavily、Bing RSS 返回结果；Exa 返回 HTTP 402；Brave 未配置。云端与后续可用性须以运行报告为准。

## 融资专用来源订阅

`financing/sources.json` 是唯一来源配置，当前 39 个入口，完整清单见 [融资信源](financing-sources.md)。覆盖国内科技/创投媒体、北美与欧洲融资媒体、印度与东南亚媒体、公告通讯社及投资机构。

`subscriptions.mjs` 提供 RSS/Atom、网页列表和 JSON 列表适配器。每项明确地区、来源层级、地址和必要的选择器；新增来源不必复制抓取逻辑。当前配置使用 RSS 和网页列表，JSON 适配器已具备测试但没有虚构的生产接口。

订阅先抓公开列表元数据，筛融资候选，再读原文判断 AI 相关性与排除边界。综合源中的非融资内容不进入正文采集。标题和摘要只用于发现，订阅成功不表示其中每篇文章可读，也不表示候选已获准收录。

来源状态保存在私有证据仓的 `financing-monitor-state/subscriptions.json`。成功条目、ETag、Last-Modified 与成功时间一起原子写入；失败保留原成功位置和仍在窗口内的候选。短 RSS 不会抹掉昨天尚在窗口内的线索。304 只能复用同配置检查点。反爬页、失效选择器、错误 JSON、403/429 等必须记录失败，不能返回虚假的空列表。

失败来源通过统一网关执行 `site:出版方域名 + AI + 融资 + 日期` 补查；搜索命中仍需读原文。健康回执分别记录订阅失败与搜索补查结果。下一次日常采集重试失败来源；同日已经接受的采集不会因补充来源失败被整体重采。订阅和精选同步是补充渠道，故障不会抹掉其他渠道成功结果，也不会阻塞已核验融资发布；报告保留 `supplemental_failures`。

只检查配置：`npm run inspect:financing-sources`。

联网检查列表与 AIHOT 精选（不调用模型、不写事实库、不发布）：

```sh
npm run inspect:financing-sources -- --live=true --selected=true --date=YYYY-MM-DD --state-dir=<私有运行目录>
```

## 原文与日期

`original-page.mjs` 使用 DOM 解析和站点规则，读取 JSON-LD `datePublished`、明确的发布时间元数据和页面日期标签；支持中文日期、英文绝对日期及嵌套 JSON-LD。不使用搜索时间、URL 路径日期、`dateModified` 或“昨天”补造发布日期。保留日期值和提取位置供追溯。

正文从文章容器提取，排除导航、推荐、分享和评论。首页、融资列表不能作为单篇融资新闻；日期缺失、不可读、未来或窗口外内容分别处理。首轮每次最多尝试 480 个 URL、并发 4，剩余候选有检查点续跑。全部原文只入私有证据库，公开仓仅保存定位符。

可选 Jina Reader 仅在 `JINA_API_KEY` 已配置时用于原网页恢复，当前没有配置，不声称已启用。恢复必须返回请求的原 URL、可读正文和原始发布时间；列表页仍不能冒充新闻。共享每日上限 20 次，调用前记录预算及回执，成功缓存；结果未知的调用同日不自动重复计费。Reader 输出仍走相同证据门禁，不能把搜索摘要换名当原文。

## AIHOT 聚合与变更同步

参考 [AIHOT 源码](https://github.com/KKKKhazix/AIHOT)，审阅提交 `035f7b7f6e26cf203562ddd6065ff7adc1bb0c07`。借鉴其适配器、来源分层、失败不推进水位和变更同步机制；融资收录不按 AIHOT 热度决定。仓库公开 18 个示例来源，并非生产完整来源表；文本搜索只检索其聚合内容。

两条互补接口同时进入发现流程：

1. `/api/v1/items?mode=all&window=7d&by=timeline&limit=100`：沿 `page.nextCursor` 拉到 `page.hasMore=false`，涵盖七天公开窗口中的入选和未入选内容。全部分页后筛融资元数据，再核验原文。重复游标或预算耗尽标记未完成，不冒充全量成功。
2. `/api/v1/selected/snapshot` + `/api/v1/selected/changes`：首次分页建立精选元数据快照，固定快照水位；之后按游标读取新增、修改、删除。只有完整验证并保存一页后才能推进游标；中断可续跑，`409 snapshot_required` 触发重新建快照。保留融资元数据，七天内候选进入当日采集；较早条目只作历史索引，不能冒充新增。上游删稿或改稿进入复核信号，不自动撤销已经独立核验的融资事实。

精选状态同样保存在私有证据仓。全公开七天窗口不等于全历史，精选快照也不等于全量内容；停机超过七天的缺口需指定历史回补。2026-10-02 初始化实测：快照及增量共 6 页，77 条融资候选元数据，其中 73 条早于当日窗口；它们不是已核验事件数。

接口依据：[sources](https://github.com/KKKKhazix/AIHOT/blob/main/docs/sources.md)、[architecture](https://github.com/KKKKhazix/AIHOT/blob/main/docs/architecture.md)、[OpenAPI](https://aihot.news/openapi-v1.json)。

## 二次搜索

先复用接受的原文及事件检查点，按最多六种查询意图依次补查：主体、本轮融资、官网产品、投资方理由、本轮公告、创始人/客户/总部。每读到新原文便重新评估缺口，已由原文覆盖的意图跳过。金额只是查询提示，不能每次都强制精确金额；未知字段保持未知。

每个意图最多增加两份成功原文，每事件最多尝试 24 次正文抓取、保留八份来源。搜索命中和实际正文均核对公司名称或别名，失败原文尝试下一个 URL。只把搜索片段作为发现线索。存在 `FUNDING-RESEARCH-SEEDS-V1` 时优先复用人工确认链接和私有缓存。

人工通过 `web.run.open` 实际阅读的原页面摘录可作为二次研究缓存，明确标为 `web_open_excerpt`，不冒充完整正文或直接 HTTP 抓取。复用必须同时通过原 URL、正文哈希、审核人、审核时间与工具来源校验；搜索摘要不适用。摘录保存在私有证据仓，仍须通过独立来源和逐项引用检查。它不修改融资原始披露日期，也不替代首轮融资原文采集。

同出版方、相同或大段转载正文、明确相同原始 URL 合并计算独立来源；两个不同链接不自动算两份独立证据。新生成融资卡至少需要两组独立来源，再通过主体、轮次、金额、投资方和逐项原文引用门禁。缺口检测只是节省查询的规划信号，不产生事实或替代模型证据审查。历史接受卡不会被本次搜索升级重复生成。

验证：`npm run test:funding-insights`、`node --test agent-workflow/tools/tests/search-gateway.test.mjs`。恢复遵循 [每日监测规则](unified-daily-monitoring.md)，不因下游失败重采接受原文。

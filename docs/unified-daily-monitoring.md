## 单次主流程

1. **核对已有状态并启动或接续生产。** 先检查当天及上次成功后遗漏日期的运行、水位、已接受原文和发布状态。不要将旧日报、成功派发或单一退出码当作当天完成。使用现有健康路由器：

   ```powershell
   node agent-workflow/tools/run-daily-automation-controller.mjs --phase=daily --date=YYYY-MM-DD --runtime-dir="D:/Fang/项目/观澜AI/runtime"
   ```

   该工具可以派发生产。只有实际需要生产时调用；单纯预检追加 `--dry-run=true`。读取其当天 JSON，区分 `waiting/publication_waiting/dispatched` 和已接受完成。对已在运行的同日期 workflow 继续跟进，不再次派发。派发后用 GitHub 状态及阶段产物确认完成，不等固定 10:00 或 16:45 时钟。国内 `china-funding-pr.yml` 与海外商业信号分别核对，不能用一个分支成功替代另一个。

2. **覆盖检查和定向补漏。** 采集产物可用后，分别检查国内/海外六类消费 AI 硬件覆盖：眼镜；钥匙扣/挂件/吊坠/胸针；玩具/陪伴；手机；耳机/录音穿戴；家庭消费设备。只对未覆盖或失败品类补检最近七天及上次成功后的遗漏日期。复用同日已接受原文及私有缓存，不因下游失败重跑全采集。Tavily/Exa 受限时使用可用搜索和公司/投资方官网发现原始链接；搜索摘要只作线索。按现有研究种子和 `--research-seeds` 路径恢复原文捕获。

3. **核验和准入。** 公司、产品、用途、轮次、原始披露日、金额、币种、投资方分别绑定原文证据；走私有存证、精确引用 Claim、事件、融资卡及展示门禁。按主体/轮次/原始日期/来源去重，保留新轮和追加轮；未知金额保持未知，不混用累计额、估值、众筹预售或产品发布。已核验消费 AI 玩具和陪伴设备可纳入，不能扩大到工业机器人、机械部件或用途未核验产品。通过现有 PR/CI/合并和 Pages 链路发布接受结果，不能降低门禁或夹带工作区改动。

4. **发布与收尾。** 已接受数据具备发布条件时立即执行收尾，无需等到 16:45。统一入口在接受产物就绪后自动进入收尾；需要单独恢复收尾时：

   ```powershell
   node agent-workflow/tools/run-daily-automation-controller.mjs --phase=final-closure --date=YYYY-MM-DD --runtime-dir="D:/Fang/项目/观澜AI/runtime"
   ```

   保留数据层刷新与校验、知识库同步、独立融资站与小程序数据、受保护 OPS、监督和问题记录。控制器自动从接受的 `origin/main` 建立隔离工作目录，数据层只读取接受数据。阶段检查点位于运行目录，绑定日期、数据提交与代码版本；成功阶段复用，失败阶段及其依赖接续。`--dry-run=true` 不执行采集、构建或发布。门户工具位于关联 `Guanlan-Funding-Portal/scripts/publish-from-wavesight.mjs`，可用 `--portal-repo` 或 `GUANLAN_FUNDING_PORTAL_REPO` 指定；默认从 Git 公共仓根解析关联门户路径，支持隔离 worktree。

   每个发布步骤单独记录。若部分步骤失败，下次只恢复失败步骤及依赖，不重新执行全量采集或已成功发布。国内/海外分别保留完成状态，一处失败不抹去另一处接受结果；共享投影仍须全部适用门禁通过。回读网站、小程序实际数据日期、版本、公司/产品/投资方展示和本批可见性；Pages 成功不等于门户上线。未通过门禁的项目保留待核验，不能混入成功统计。

5. **汇总与通知。** 当天只维护一份总体结果；只有有可行动的新融资、重要更正、持续失败或需用户处理时通知，无变化及例行成功保持安静。尚有必要步骤未完成时报告具体阶段，不声称全天完成。单次运行内持续跟进已经派发的任务；若环境或外部依赖持续阻塞，保存恢复点并报告，下一次运行先恢复。不要新建轮询自动化或把旧时钟恢复为补救。

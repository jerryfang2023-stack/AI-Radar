# 周报/月报标题批量重写要求

请逐篇读取输入的 15 篇已发布周报/月报全文，严格执行标题 Skill。用户只需要最终标题，因此候选生成、reference/seed、Eval 和标题承诺卡可在内部完成，最终仅输出一个 JSON 对象，不要输出 Markdown 代码围栏。

JSON 格式：

```json
{
  "reports": [
    {
      "date": "YYYY-MM-DD",
      "kind": "weekly-report 或 monthly-report",
      "source_file": "文件名",
      "current_title": "原标题",
      "recommended_title": "最终推荐标题",
      "primary_type": "Pxx",
      "devices": ["Dxx", "Dxx"],
      "reference_ids": ["Pxx-Rxx"],
      "seed_ids": ["LSxx 或 original_expression"],
      "evidence_refs": ["正文中的 E/O/C ID 或可核对事实"],
      "promise": "标题承诺，最多一句",
      "rationale": "为什么该标题最能代表本文且不夸大，最多一句"
    }
  ],
  "batch_audit": {
    "duplicate_structures": [],
    "eval_hits": [],
    "unsupported_claims": []
  }
}
```

硬性要求：

1. `reports` 必须恰好 15 条，每个输入文件一条，不漏、不重复，按日期升序，同日周报在月报之前。
2. 先为每篇内部生成至少三种不同结构，再推荐一条；不得只做同义改写。
3. 标题必须基于该篇正文的最强事实与核心判断，不得把其他报告的数字或结论串入。
4. 标题使用简体中文，建议 16—34 个可见字符；必要的 AI、Agent、AI Coding、Token 可保留。
5. 全批次结构必须显著多样：最多两条使用“不是……而是……/缺的是……”骨架；最多两条使用冒号；最多两条使用问号；不得连续三条用同一语序；至少覆盖数字事实、动作后果、真实问题、判断式、场景式等不同点击理由。
6. 禁止使用当前批次里已经过度重复的万能词组来制造假张力，包括“真正”“不缺模型”“缺的是”“越……越……”，除非该篇存在不可替代的真实对立，且全批次不超过上述数量。
7. 不写“周报”“月报”标签，不写“格局已变”“未来已来”“赋能”“重塑”“值得关注”“背后逻辑”等空泛表达。
8. 对数字标题逐字核对正文；对于“微软 25 亿”等歧义金额，只有正文能证明币种、交易性质与标题因果时才可保留。
9. `batch_audit` 三个数组必须为空；若不为空，先自行修订再输出。
10. 本次用 DeepSeek Pro 做批量复核，生成记录中的模型名必须真实返回。

本次复核追加要求：上一轮候选把前三篇连续写成“X 张信号卡里，Y 张……”且大量使用 P01 数字标题，这仍然属于机械同构，必须全部重新判断。全批次数字开头标题不得超过三条，P01 不得超过四条；相邻报告不得使用相同主类型。输入只包含 15 篇正式发布稿，必须包含 `2026-08-31` 月报，不得混入 `2026-08-29` 的 superseded 融资稿。最终 JSON 不得包裹代码围栏。

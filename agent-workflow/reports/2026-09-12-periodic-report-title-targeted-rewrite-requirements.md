# 数字标题过密的定向复核

请严格执行标题 Skill，只处理输入的 7 篇报告。上一轮标题连续采用数字开头，仍显机械。本轮每篇输出三条可发布候选和一条推荐，最终只输出 JSON，不要 Markdown 代码围栏。

每篇三条候选必须分别采用：

1. 动作—后果型：以具体主体/动作及经营后果组织，不以数字开头；
2. 真实问题型：正文确实回答的问题，可用问号，但不得故弄玄虚；
3. 判断/场景型：像经营者或行业观察者自然会说的话，不用万能反差模板。

全批次硬性约束：

- 不用“不是……而是……”“缺的是……”“真正……”“越……越……”骨架；
- 最多两条候选用冒号，最多两条候选用问号；
- 数字可以进入标题，但不得位于开头，也不得让标题退化成数据摘要；
- 不重复“X 张卡里，Y 张……”或“X 之后，Y”结构；
- 每项数字、公司、动作和结论必须逐字受该篇正文支持；
- 6 月月报不得采用“48% 超过 32% 和 20% 之和”的错误算术，只能写案例信号超过产品发布；
- 保留正文最强商业利害，标题建议 16—34 个可见字符。

JSON 格式：

```json
{
  "reports": [
    {
      "source_file": "文件名",
      "candidates": [
        {"title": "...", "structure": "动作—后果型", "evidence_refs": ["..."], "eval_hits": []},
        {"title": "...", "structure": "真实问题型", "evidence_refs": ["..."], "eval_hits": []},
        {"title": "...", "structure": "判断/场景型", "evidence_refs": ["..."], "eval_hits": []}
      ],
      "recommended_title": "...",
      "promise": "...",
      "rationale": "..."
    }
  ]
}
```

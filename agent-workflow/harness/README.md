# 观澜 AI Harness

Harness 将任务、规则、设计、执行能力、验证和交付证据串成可追踪的工作机制。规则正文、业务代码和运行证据保留在原事实源，本目录只维护关联与通用完成标准。

## 入口与事实源

- [关联清单](manifest.json)：稳定流程 ID、现有模块 ID、四类引用、验收标准、恢复方式及既有治理任务编号。
- [模块完整性模板](module-completeness-template.md)：新增模块或改变契约时使用；已有资料通过引用复用。
- [V4 执行流程](../../context/06-execution-harness.md)：事实生产的专项流程。
- [自动化职责](../../context/08-automation.md)：当前调度及恢复职责。
- 模块名称与责任角色以独立知识库 `90-工作区/00-统一管理/registry.json` 为准。Harness 只引用已有模块 ID，不维护第二套模块责任表。
- 人工入口是上述统一管理台的 Harness 页签；知识库根目录生成投影不接受人工修补。

## 三层与执行底座

| 分类 | 管什么 | 典型文件 |
|---|---|---|
| rules / 约束 | 事实准入、权限、范围、禁止行为 | AGENTS、当前规则、Skill 边界 |
| design / 设计 | 要交付的行为、数据、接口、状态 | schema、产品设计、接口与页面契约 |
| execution / 执行底座 | 实际执行步骤和依赖 | Skill、程序、工作流、发布器 |
| closure / 交付完整性 | 是否达到完成标准 | 测试、人工验收规范、质量门、发布与恢复证据 |

一个文件可以承担多个角色；引用关系不等于复制文件。历史 H5 作为受限参考登记，不默认进入现役发布流程。AIP 与个人内容技能为协作边界，不扩大项目认证或启用范围。

## 使用方法

1. 按模块或流程找到清单项，阅读所需的约束与设计源。
2. 明确改动、成功标准和涉及的上下游，按已有授权执行。
3. 在登记的工作目录运行适用检查；清单命令只供人工选择，索引工具从不执行这些命令。
4. 记录验证时间、源码提交或未提交文件哈希、输入版本、结果及未覆盖项。涉及发布再附 release、线上回读与恢复入口。
5. 修改规则或文件路径时，同步关联及生成物；生产故障引用原 incident，治理事项引用原 GOV 编号，不复制队列。

文件存在、确定性测试、真实模型评测、推送、部署和线上验证分别记录。旧证据只能证明当时版本；引用检查通过不代表业务验收通过。UI 的加载、空数据、报错、权限不足和重试，以及算法的冲突、重复、过期和误判样本，按模块适用性验收。

## 只读检查

在 WaveSight 执行 `npm run assert:harness`：检查本仓引用、唯一 ID、完整四类映射及安全路径。CI 未挂载的外部仓标为待核验，不能伪装已通过。

本机从统一管理目录运行 `刷新管理台.ps1`，会传入现有路径登记，生成 Harness 视图及 `reports/harness.json`。检查只读取登记与引用存在性，不读取业务数据库、原文正文或密钥，不启动采集、模型或部署。只读检查进入现有代码检查工作流，没有新增定时任务。

`manifest.json` 内使用根标识与相对路径。本机绑定仍由项目路径登记和迁移工具维护；管理台的绝对路径是可重建展示数据，不提交到公共清单。

## 维护与退出

清单随生产代码进入 Git；本机证据关联在统一管理目录 `harness-evidence.json`。运行镜像从所属源同步；注册、发现、启用、认证和模型实测是不同状态。

历史证据保持原貌并退出默认规则读取。删除必须经过具体用途、引用、运行占用、唯一状态与恢复条件核验。本轮历史清理只登记候选，不能按相同哈希直接删除 Skill 镜像、数据库、原稿或发布凭据。

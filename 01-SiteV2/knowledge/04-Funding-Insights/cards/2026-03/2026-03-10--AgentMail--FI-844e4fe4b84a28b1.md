## 产品

### AgentMail API 平台

为 AI 智能体提供专用电子邮件收件箱的 API 平台，支持双向对话、解析、线程、标签、搜索和回复。一个 API 调用即可创建收件箱，无需 OAuth 流程或人工设置。

- **目标客户**：构建 AI 智能体的开发者
- **关键能力**：
  - 双向对话（发送、接收、线程、回复）
  - 结构化数据解析
  - 标签和搜索
  - Webhooks 和 WebSockets 实时事件推送
  - 与 LangChain、LlamaIndex、CrewAI 等框架集成
  - 内置垃圾邮件检测和安全投递优化

### AgentMail 入职 API

允许 AI 智能体直接自行注册并创建电子邮件收件箱的 API，无需开发者介入。

- **目标客户**：AI 智能体
- **关键能力**：
  - 智能体自主注册
  - 自动创建收件箱
  - 无需人工介入

## 资本判断

> [!analysis] 应用层判断
> 资本押注的核心变量是：电子邮件作为互联网既有的身份和通信原语，能否成为 AI 智能体经济的基础设施层。本轮融资所依赖的已验证信号包括：OpenClaw 发布后用户数一周内增长三倍、二月增长四倍，验证了智能体对专用邮件基础设施的突发性需求；超过 500 家 B2B 客户和数十万智能体用户表明产品已找到市场契合点；DoAnything、Pancake、AISDR 等客户案例证明智能体邮件在工作流中产生了可量化的效率提升。但当前证据仅限于早期采用者数据和单一基础设施假设的验证，尚未证明该身份层能在协议层竞争（如 A2A）和去中心化方案（如 ERC-8004）的夹击下持续捕获价值。

### 已验证信号

- OpenClaw 发布后用户数一周内增长三倍，二月增长四倍，验证了智能体对专用邮件基础设施的突发性需求
- 超过 500 家 B2B 客户和数十万智能体用户，表明产品已找到早期市场契合点
- DoAnything、Pancake、AISDR 等客户案例证明智能体邮件在工作流中产生了可量化的效率提升（响应时间从数小时降至数分钟，创始人沟通开销降至接近零）
- 智能体已开始自主搜索、发现并注册 AgentMail，无需开发者介入，验证了智能体对身份基础设施的自发性需求

### 证据边界与风险

- 中心化架构依赖：AgentMail 收件箱依赖其自身基础设施，对于需要去中心化、抗审查环境的智能体场景，这可能成为采用障碍，而 ERC-8004 等链上身份方案提供了替代路径。
- 协议层竞争：Google A2A 等协议级标准若获得广泛采用，可能将智能体通信标准化为协议而非平台，削弱 AgentMail 作为平台的价值捕获能力。
- 滥用与安全风险：为 AI 智能体提供电子邮件地址使滥用更容易，当前的安全措施（每日 10 封外发邮件上限、速率限制、关键词过滤）可能随着平台规模扩大而不足以应对新型攻击向量。

## 同类对照

### SendGrid

- **产品/方案**：事务性邮件 API
- **场景**：单向通知发送，如密码重置、订单确认
- **目标客户**：需要发送事务性邮件的人类开发者
- **核心差异**：SendGrid 等传统事务性邮件 API 仅支持单向发送通知，而 AgentMail 为智能体提供完整的双向对话收件箱，支持接收、线程、解析和回复。

### Mailgun

- **产品/方案**：事务性邮件 API
- **场景**：单向通知发送
- **目标客户**：需要发送事务性邮件的人类开发者
- **核心差异**：Mailgun 等传统事务性邮件 API 仅支持单向发送通知，而 AgentMail 为智能体提供完整的双向对话收件箱，支持接收、线程、解析和回复。

### Gmail

- **产品/方案**：人类电子邮件服务
- **场景**：个人或企业日常邮件通信
- **目标客户**：人类用户
- **核心差异**：Gmail 为人类用户设计，对 API 施加速率和容量限制，不适合智能体大规模部署；AgentMail 专为智能体构建，提供无 UI 元素的 API 优先体验，且无类似速率限制。

### Google A2A

- **产品/方案**：智能体到智能体协议
- **场景**：跨框架智能体发现与协作
- **目标客户**：需要跨框架互操作的 AI 智能体开发者
- **核心差异**：A2A 是协议层标准，专注于智能体之间的结构化消息传递和发现；AgentMail 则利用现有的电子邮件基础设施，使智能体能够与任何已接受电子邮件的服务或人类进行交互，无需对方采用新协议。

### Sending Labs

- **产品/方案**：区块链原生智能体消息传递
- **场景**：需要加密证明的智能体间通信
- **目标客户**：需要去中心化、抗审查通信的 Web3 智能体开发者
- **核心差异**：Sending Labs 采用去中心化的区块链原生消息传递方式，需要智能体采用特定协议；AgentMail 采用中心化的电子邮件方式，提供与现有互联网服务的即时互操作性，无需对方改变行为。
